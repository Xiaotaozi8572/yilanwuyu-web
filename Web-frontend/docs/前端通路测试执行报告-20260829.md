## 8. 缺陷登记（BUG）

### BUG-01（S2，已修复）：语音结束信号永远发不出，语音转文字链路完全失效

| 项 | 内容 |
|---|---|
| 发现方式 | 用户人工执行语音通道测试（按住麦克风说话，松开后无转写） |
| 现象 | 按住麦克风说话、松开后，无任何转写或回答（此前自动化未覆盖真实按键路径，故首轮报告未发现） |
| 根因 | `src/services/voiceWsClient.js` `sendAudioEnd()` 守卫条件写反：`if (!this.isOpen \|\| !this.audioEnded) return`。`audioEnded` 初始为 false 且只在本函数内置 true，首次调用必然被 `!this.audioEnded` 拦截 → **audio.end 一次都发不出去** → 后端一直等帧直到 120s 空闲超时 |
| 证据链 | ① Python e2e 直连 WS（自带 audio.end）转写正常 → 后端 ASR 无辜；② Node 加载真实前端 `VoiceWsClient` 模块复现：修复前 sendAudioEnd 静默返回；③ 修复后同脚本 PASS：252 帧 → audio.end 上线 → `asr.final: C919的发动机型号是什么?` → answer.display |
| 修复 | 一行：守卫改为 `if (!this.isOpen \|\| this.audioEnded) return`（与 sendAudioFrame 的防重发模式对齐）；连带修复 turnUsed 置位，多轮换 turn 逻辑恢复 |
| 影响 | 语音输入通道（按住说话）自初始提交起完全不可用；文字通道不受影响 |
| 回归验证 | `挑战杯前端/tmp/verify_voice_client.mjs`（Node 直载真实客户端模块的端到端脚本，可复跑）；浏览器端建议人工再测一轮 TC-VOICE-01~04 |
| 状态 | ✅ 已修复并验证（2026-08-29） |

### BUG-02（S1，已修复）：AudioWorklet 采样率引用错误，语音帧从未产出

| 项 | 内容 |
|---|---|
| 发现方式 | 用户人工语音测试（收到"请说得更完整一些"澄清），随后浏览器 A/B 对照实验定位 |
| 现象 | 按住麦克风说话松开后，无转写；后端返回 no_speech_detected 澄清（前端映射缺失显示兜底文案） |
| 根因 | `public/pcm-processor.js` 把 `sampleRate` 写成 `this.sampleRate`。AudioWorklet 中 sampleRate 是 **AudioWorkletGlobalContext 的全局属性**（同 currentTime），实例上为 undefined → `ratio = undefined/16000 = NaN` → 重采样条件 `resampleCount >= NaN` 永假 → accumulator 永远为空 → **无论 AudioContext 什么采样率，帧数为 0** |
| 定位证据 | A/B 对照：同一 AudioContext 同一麦克风流，Blob 内联 worklet 收到 4913 次输入，项目 worklet 零帧（模块加载成功、节点创建成功）；ScriptProcessor 对比确认音频图活跃、麦克风有信号 |
| 修复 | 两处 `this.sampleRate` → 全局 `sampleRate`（process 分支判断 + pushResampled 的 ratio 计算），并加注释防回归 |
| 验证 | 修复后浏览器实测：6 秒 396 帧（约 66 帧/秒）、每帧 640 字节（20ms@16kHz Int16 正确规格）；真实页面按住→松开→后端正常返回响应（底噪环境下为"识别为空"澄清，属预期） |
| 影响 | 语音输入通道自初始提交起零帧产出（与 BUG-01 叠加，语音功能从未真正工作过） |
| 状态 | ✅ 已修复并验证（2026-08-29） |

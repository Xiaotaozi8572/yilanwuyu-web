## 1. 通路架构与测试重点

### 1.1 当前通路拓扑

```
浏览器（Chrome / Edge / Firefox）
   │  http://localhost:5173（Vite dev）
   ▼
挑战杯前端（Vue 3.5.39 + Vite 8.1.1 + Three.js 0.180）
   │  唯一后端依赖点：AI 助手面板 CoachChatPanel.vue
   │  连接地址：.env.development → VITE_VOICE_WS_URL=ws://127.0.0.1:8765
   ▼ WebSocket
语音后端（uv Python 3.11.13 + PYTHONPATH 依赖方案）
   │  ASR: whisper（本地，启动时预热）
   │  RAG: 本地知识库检索（bge_m3 向量）
   │  LLM: qwen3.7-plus（阿里云百炼，enable_thinking=false）
   │  TTS: edge-tts
   ▼
用户听到语音播报 / 看到文字答案
```

### 1.2 与旧通路的差异（重要）

| 项 | 旧状态 | 当前状态 |
|---|---|---|
| 后端文件夹名 | `挑战杯` / `挑战杯后端第二版` | `挑战杯后端` |
| Python 启动方式 | 项目 `.venv\Scripts\python.exe` | **uv 全局 Python + PYTHONPATH 指向 site-packages**（项目自带 `.venv` 的 python.exe 损坏，勿用） |
| LLM 供应商 | deepseek（默认）/ qwen 必超时 | **qwen3.7-plus，超时已修复**（请求体显式携带 `enable_thinking=false`） |
| LLM 密钥 | 终端临时设置 | 终端临时设置（系统与文件中均未保存，每次启动须重设） |
| LLM 响应时间 | 超 60s 必超时降级 | 实测 15.5s ~ 57.3s 波动 |
| 残留进程 | 曾有 8766/8767 残留 | 已清理，端口 8765/8766/8767 空闲 |

## 13. 已知问题与预期行为（防误报，必读）

> **本章现象在测试中出现时，按本章方式记录，不要作为新缺陷提交。**

### 13.1 LLM 回答偶发转澄清

- **现象**：介绍型问题偶发收到澄清式追问而非答案（后端 reason 为 `pipeline_response_unavailable`）。
- **原因**：LLM 输出随机性导致部分回答未通过后端信任校验门，属后端管线 fail-closed 设计；同一问题重问可能通过。
- **处置**：重问一次；若连续 3 次同一问题都澄清，记录到《已知问题观察表》（附录 C）供后端排查，不计前端缺陷。

### 13.2 响应时间波动大（15~57s）

- **现象**：同一类问题有时 15s 有时近 60s。
- **原因**：qwen 服务端负载波动；已关闭思考模式（修复后），仍受网络与服务端影响。
- **处置**：超过 60s 触发澄清/降级属当前已知边界；如高频发生（>30% 查询），提请后端放宽 `providers.yaml` 的 `timeout_ms`。

### 13.3 文字答案后偶发 TTS 错误提示

- **现象**：文字回答已正常显示，随后面板出现 TTS 相关错误信息。
- **原因**：后端 TTS（edge）合成为异步遗留事件，生产媒体服务未接入为已知限制，不影响文字答案本身。
- **处置**：忽略；仅当**语音通道完全无任何播报**且持续复现时才记录观察表。

### 13.4 生产构建后 AI 助手不可用

- **现象**：`npm run build` + `npm run preview` 下 AI 助手无法连接。
- **原因**：`.env.production` 的语音地址为占位符 `wss://your-domain.example.com/voice-ws`（部署前须替换），属预期设计。
- **处置**：不算缺陷；测试语音一律用 `npm run dev`。

### 13.5 知识库检索未覆盖的参数

- **现象**：个别参数问题（如"最大起飞重量"）转澄清，但知识库中该数据存在（77,300kg）。
- **原因**：RAG 检索召回不足（后端已知问题）。
- **处置**：记入观察表，转后端处理，不计前端缺陷。

### 13.6 弱网下 AI 响应显著变慢

- **现象**：Slow 3G 模拟下提问耗时大幅增加。
- **原因**：网络限速直接作用于 WS 传输与云端调用。
- **处置**：只要最终有明确结果（答案或失败提示）即算通过（见 TC-PERF-08）。

## 15. 禁令清单（红线）

1. **禁止**把密钥写入任何文件、截图、BUG 单或聊天记录（密钥只存在于终端 `$env:` 临时变量中）
2. **禁止**使用项目自带的 `.venv\Scripts\python.exe` 启动后端（该解释器损坏，指向不存在路径）
3. **禁止**在未确认 Whisper 预热完成（终端打印监听地址）前判定"服务连不上"为缺陷
4. **禁止**把第 13 章任何已知现象直接当新 BUG 提交（先按 13 章处置流程走）
5. **禁止**用 `npm run build` / preview 环境测试语音通路（生产语音地址为占位符，见 13.4）
6. **禁止**同时启动多个后端实例（会争抢 8765 端口；测试 8766/8767 端口被占属异常，须排查残留进程）
7. **禁止**跳过 9.4（现为 14.4）截图留证直接填"通过"——计时类、语音类、性能类用例尤其必须留证
8. **禁止**在 BUG 单里粘贴超长 Console 原文（只贴与现象相关的报错段落）
9. **禁止**修改 `providers.yaml`、`qwen_client.py` 等后端配置代码来"顺手修一下"（后端变更走后端流程，前端测试只记录）
10. **禁止**在性能计时用例执行期间开下载、看视频等抢占资源的操作（测量环境失真，数据作废须重测）
11. **禁止**把单次测量当结论——性能指标一律 3 次取中位数，AI 响应抽样至少 10 条
12. **禁止**测试结束后不清理：须关闭前端 dev（Ctrl+C）并按需保留/停止后端，明确告知团队当前后端状态

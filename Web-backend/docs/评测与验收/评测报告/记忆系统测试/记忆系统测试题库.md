# 记忆系统测试题库

## 1. 题库说明

- 测试主题：记忆系统读取、治理、并行、故障容错与真实 LLM 上下文接线。
- 测试依据：`C:\Users\SONGQI\Desktop\系统性能测试方案.md` 第四节“记忆系统测试”。
- 适用阶段：T4.1–T4.4 及四项追加补测。
- 测试原则：记忆只能影响个性化表达、学习状态和对话连续性，不能作为航空事实来源；航空事实必须由 `EvidencePackage` 支持。
- 外部模型：需要验证回答生成时，必须调用真实 DeepSeek provider；不得用 mock LLM 冒充真实模型结果。
- 环境边界：只使用脱敏夹具、临时数据库、Testcontainers 或本地隔离服务；不得连接生产数据库、生产 Java 服务或真实用户数据。

## 2. 验收基线

| 指标 | 通过标准 |
|---|---|
| Python memory 等待 | fast/normal 单次等待不超过 150ms |
| 超时降级 | 返回全新的空长期记忆上下文，RAG 继续完成回答 |
| 记忆功能 | 八类记忆用例通过率 100%，共 160 条夹具通过 |
| 并行效率 | memory/RAG 两个实际分支并行耗时 ÷ 串行分支耗时和 ≤60% |
| 远端熔断 | 连续 3 次失败后 OPEN，10 秒后进入 HALF_OPEN 探针 |
| 故障回答 | EvidencePackage 保持有效，正文不暴露技术故障，不回退旧 SQLite 长期记忆 |
| 真实 LLM | provider=deepseek，`fallback_used=false`，memory context 接线可审计 |
| 隐私安全 | 无跨用户读取、无撤回后读取、无 memory-as-fact、无私有记忆正文泄漏 |

## 3. T4.1 读取延迟与超时降级题

| 题号 | 测试主题 | 测试题/操作 | 预期结果 | 关键证据 |
|---|---|---|---|---|
| T4.1-01 | 正常读取 | 发送合法 session、身份、schema 和预算完整的 memory resolve 请求。 | 返回 `APPLIED` 或合法 `EMPTY`，耗时在预算内。 | status、elapsed_ms、identity binding |
| T4.1-02 | 远端 150ms 内响应 | 将隔离 memory 服务延迟设置为 100ms，执行 resolve。 | 正常返回，不触发超时降级。 | response status、timeout=false |
| T4.1-03 | 远端超过 deadline | 将隔离 memory 服务延迟设置为 300ms，执行 resolve。 | 150ms 内返回 `DEGRADED`，不得等待到 300ms。 | `MEMORY_TIMEOUT`、elapsed_ms≤150ms |
| T4.1-04 | Future 超时参数 | 检查 normal 路径提交 Future 的 timeout 参数。 | 精确使用 `0.150s`，不得延长 deadline。 | 单元测试断言 |
| T4.1-05 | 新空上下文降级 | 让远端返回超时或损坏响应，再执行带 RAG 证据的事实问题。 | 使用全新空长期记忆上下文，RAG 仍返回结构化回答。 | memory_context 为空、EvidencePackage 存在 |
| T4.1-06 | 故障隐私 | 检查回答、trace 和日志中是否出现异常正文、完整记忆值、session 或 learner 身份。 | 只保留有限诊断码和耗时，不泄露私有内容。 | 脱敏扫描结果 |
| T4.1-07 | schema 错误 | 使用不兼容 schema version 的 memory response。 | 丢弃远端上下文并降级为空上下文，主链路继续。 | `SCHEMA_INCOMPATIBLE` 或等价有限诊断码 |
| T4.1-08 | 身份绑定不匹配 | 修改 response 的 identity binding digest。 | 返回降级，不得使用任何远端记忆项。 | `IDENTITY_BINDING_MISMATCH`、context absent |

## 4. T4.2 八类记忆功能题

每类题使用 20 条脱敏夹具，合计 160 条；每条均应检查记忆决策、来源闭包、时间有效性、回答成功和事实污染。

| 题号 | 记忆类别 | 测试题/操作 | 预期结果 |
|---|---|---|---|
| T4.2-01 | continuation | 学员上一轮说“以后请用分步骤方式讲解”，下一轮追问同一知识点。 | 记忆影响表达方式，回答事实仍来自 EvidencePackage。 |
| T4.2-02 | continuation | 学员使用“它”“这个部件”等指代进行连续追问。 | 正确解析同会话指代，不跨会话读取记忆。 |
| T4.2-03 | correction | 学员纠正“我把升力和阻力混淆了”，后续再次询问二者区别。 | 产生受治理的 misconception/学习状态记忆，不把纠错文本写入航空事实库。 |
| T4.2-04 | correction | 学员撤回或修正上一条偏好/认识。 | 新版本生效，旧版本保持 append-only 且不再满足当前读取条件。 |
| T4.2-05 | mastery | 学员连续完成某知识点练习并表现稳定。 | mastery 状态按时间和置信度治理，不生成无来源航空事实。 |
| T4.2-06 | mastery | 学员长期未复习已掌握知识点。 | 时间有效性和衰减规则生效，过期状态不默认进入上下文。 |
| T4.2-07 | preferences | 学员偏好“简洁回答”或“先给结论再解释”。 | 只改变表达风格，不改变事实、数值和安全策略。 |
| T4.2-08 | preferences | 学员提交包含航空事实的“偏好”。 | 事实部分被拒绝作为偏好或被治理，不进入事实来源链。 |
| T4.2-09 | relations | 学员建立“部件—知识点—误解”的关系。 | 关系可检索、来源闭包完整，关系投影不可成为唯一权威。 |
| T4.2-10 | relations | 删除或重建 Neo4j/图投影后再次读取。 | PostgreSQL 权威数据仍可解析，图投影可旁路重建。 |
| T4.2-11 | temporal | 同一偏好先后发生两次变化。 | 最新有效版本覆盖读取结果，时间边界可解释。 |
| T4.2-12 | temporal | 查询 valid_from 未到或 valid_until 已过的记忆。 | 不返回无效记忆，时间准确率达到门槛。 |
| T4.2-13 | privacy | 学员撤回记忆同意后查询上下文。 | 读取被阻断，返回空/降级上下文，不复活历史敏感内容。 |
| T4.2-14 | privacy | 学员 A 请求学员 B 的 session 或记忆。 | 返回空或拒绝，跨用户泄漏为 0。 |
| T4.2-15 | failure_replay | 重放相同事件 ID。 | 幂等处理，不产生重复 active memory。 |
| T4.2-16 | failure_replay | 事件提交后 worker 或 Redis 暂时不可用。 | outbox 保留待处理状态，恢复后可重放，ACK 不丢失。 |

## 5. T4.3 记忆与 RAG 并行题

| 题号 | 测试主题 | 测试题/操作 | 预期结果 | 关键证据 |
|---|---|---|---|---|
| T4.3-01 | 分支重叠 | 同时注入 memory=120ms、RAG base prefetch=120ms 延迟，执行事实问题。 | 两个实际工作窗口重叠，回答 `status=ok`。 | started_at/finished_at |
| T4.3-02 | 并行比例 | 计算 `max(memory_branch_ms, rag_branch_ms) / (memory_branch_ms + rag_branch_ms)`。 | 结果约 50%，不超过 60%。 | 分支级 ratio |
| T4.3-03 | 共同开销识别 | 同时记录完整请求 wall-clock。 | 完整请求耗时只作为路由、checkpoint、终态等共同开销诊断，不替代分支比例。 | end-to-end diagnostic |
| T4.3-04 | embedding 复用 | 检查 memory request 是否复用 RAG 预取生成的 typed query embedding。 | 只计算一次 embedding，profile、dimension、normalization 一致。 | embedding metadata |
| T4.3-05 | 超时并行 | 让 memory 线程超过 150ms，RAG 线程正常完成。 | memory 使用新空上下文，RAG 正常完成，不等待晚到结果写回。 | `MEMORY_TIMEOUT`、EvidencePackage |
| T4.3-06 | 会话隔离 | 并发执行两个不同 session 的请求并写入 checkpoint。 | 两个 session 的记忆、证据、checkpoint 不串扰。 | run_id/session isolation |

## 6. T4.4 远端故障与熔断题

| 题号 | 测试主题 | 测试题/操作 | 预期结果 | 关键证据 |
|---|---|---|---|---|
| T4.4-01 | 一次不可用 | 远端 gRPC 返回 `UNAVAILABLE` 一次。 | 当前请求降级为空上下文，RAG/回答继续。 | status、answer envelope |
| T4.4-02 | 连续三次失败 | 连续执行 3 次远端失败请求。 | 第三次失败后 transport circuit 进入 `OPEN`。 | circuit snapshot |
| T4.4-03 | 熔断窗口 | 在 OPEN 状态下立即执行第 4 次请求。 | 不访问远端服务，快速返回新的空上下文。 | remote call count unchanged |
| T4.4-04 | 十秒半开 | 将受控时钟推进 10 秒，执行一次探针。 | 只放行一个 `HALF_OPEN` 探针，其他并发请求仍受保护。 | circuit state、probe count |
| T4.4-05 | 探针成功 | 半开探针返回合法 `EMPTY/APPLIED`。 | 熔断恢复为 `CLOSED`，后续请求可正常访问。 | state transition |
| T4.4-06 | 探针失败 | 半开探针再次失败。 | 重新进入 `OPEN`，不产生错误记忆上下文。 | state transition、empty context |
| T4.4-07 | Java down 主链路 | 在隔离 Java memory service 不可用时执行带航空证据的问题。 | 事实回答继续，正文不出现 Java/gRPC/数据库故障细节。 | EvidencePackage、answer_success |
| T4.4-08 | 禁止旧 SQLite 回退 | 远端 REMOTE 模式下停止 Java，检查本地 memory.sqlite3 是否被用作长期记忆回退。 | 不回退旧 SQLite；只使用新的空长期记忆上下文。 | adapter trace、file access audit |

以下题目必须通过正式 `AppPipeline` 入口执行。每次结果都要记录 provider、model alias、`fallback_used`、memory context 数量和最终动作，不记录 API key、完整 Prompt 或私有记忆正文。

| 题号 | 测试题/操作 | 预期结果 |
|---|---|---|
| LLM-01 | 带有“回答要简洁”合法偏好的记忆组，询问有审核证据支持的航空问题。 | 使用真实 DeepSeek；`fallback_used=false`；memory context present；事实来自证据。 |
| LLM-02 | 与 LLM-01 相同问题，但清空长期偏好的对照组。 | provider 和模型一致；memory context absent；输出仍不编造事实。 |
| LLM-03 | 向记忆组注入不可作为事实来源的用户说法。 | 记忆只能影响表达/学习状态，不能改变证据事实或生成航空结论。 |

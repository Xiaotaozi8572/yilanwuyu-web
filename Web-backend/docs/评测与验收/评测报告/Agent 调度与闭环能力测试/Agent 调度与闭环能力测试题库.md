# Agent 调度与闭环能力测试题库

## 一、题库说明

本题库用于验证 Agent 在航空知识问答场景中的调度、检索闭环、自检降级、多轮上下文解析和故障恢复能力。

- 对应测试主题：系统性能测试方案第三节“Agent 调度与闭环能力测试”
- 覆盖范围：T3.1–T3.5
- 建议模式：口头问答 + 自动化复测 + trace 证据核验
- 核心原则：不能只看最终答案，应同时检查动作决策、证据门、状态转换、检索轮次和安全降级结果

## 二、T3.1 Agent 调度与检索契约

### 基础题

1. Agent 收到“C919 升力是什么？”后，通常需要经过哪些状态？
2. Agent 如何判断一个问题应使用 keyword、dense、parent、scene 或 graph 通道？
3. 为什么检索计划必须记录 `channels`、`top_k`、`required_evidence_types` 和过滤条件？
4. `confident`、`weak`、`conflict` 和 `not_run` 分别表示什么？
5. 为什么“检索到了文本”不等于“证据足以生成最终事实答案”？
6. AG600“这个船型机身有什么特点”场景中，Agent 如何避免把场景对象误绑定到 C919 发动机？
7. 当 scene 或 graph 通道按配置禁用时，评测结果应如何解释？
8. “C919 发动机推力参数是多少”缺少审核参数时，Agent 应输出具体数值、澄清还是人工复核？为什么？

### 进阶题

9. 如果检索计划要求 `parameter`，但返回证据没有审核参数值，证据门应如何处理？
10. 两个来源给出互相冲突的涵道比时，Agent 为什么不能任选一个来源直接回答？
11. “你说的涵道比不对，请核验”为什么应生成新的定向检索计划，而不是重复原检索？
12. 如何从 trace 证明某个禁止主张没有被输出？

### 参考核验点

- 是否经过 `PROMPT_ROUTED`、`RETRIEVAL_PLANNED`、`EVIDENCE_READY` 等状态。
- 是否记录实际通道、证据门状态、缺失证据码和冲突来源。
- 参数事实是否满足权威等级与参数来源要求。
- 冲突场景是否保留冲突并转为澄清或人工复核。

## 三、T3.2 Agent 自主补检与闭环

### 基础题

13. 什么情况下自检结果应为 `RETRIEVE_MORE`？
14. `RETRIEVE_MORE` 与 `REWRITE_ONLY` 的处理路径有什么区别？
15. 补检时为什么必须消费冻结的 retrieval directive，而不能重新猜测检索意图？
16. 补检后为什么要重新执行 evidence gate？
17. 补检后为什么必须重新生成答案并再次自检？
18. `max_retrieve_loops=2` 的作用是什么？
19. `recovery_top_k_increment=5` 应如何在 trace 或检索计划中体现？
20. 什么是“无进展补检”？检测到无进展后 Agent 应如何终止？

### 场景题

21. 首轮证据只有 C919 概览，没有巡航速度；自检发现缺少巡航速度证据。请描述下一轮 Agent 调度动作。
22. 补检返回的证据与首轮证据完全相同，且检索指纹没有变化。系统应该继续循环吗？
23. 补检返回了与原证据 ID 相同但内容不一致的证据，系统应如何处理？
24. 如何用测试证据证明发生了“检索—再生成—再自检”闭环，而不是只证明接口返回成功？

### 参考核验点

- `retrieve_round` 是否从 0 增加到 1。
- top-k 是否按配置增量。
- 新旧证据是否合并，证据 ID 是否保持一致性。
- generation request 是否重新发送，prompt context/evidence fingerprint 是否变化。
- recovery action 是否在最大轮次内收敛。

## 四、T3.3 自检失败与安全降级

### 基础题

25. 自检服务抛出异常时，Agent 的默认安全动作应该是什么？
26. `HUMAN_REVIEW` 与 `ASK_CLARIFICATION` 的适用场景有什么区别？
27. 为什么自检异常时不能直接发布已经生成的草稿？
28. fail-closed 路径中为什么要清空或禁止发布 claim candidates？
29. 未知或非法 action 为什么不能被当作 `PASS` 处理？
30. 自检失败时是否应该继续触发 retrieval recovery？请说明边界。

### 场景题

31. 自检服务抛出 `SIMULATED_SELF_CHECK_FAILURE`，请给出预期的响应状态、动作决策、claim 状态和终态。
32. 模型返回正文包含事实，但 `claim_candidates` 为空，self-check 报告 `BODY_CLAIM_UNDECLARED`。系统应该如何处理？
33. 真实 LLM 返回结构化 JSON，但答案类型与计划不一致，Agent 应继续发布还是转入安全降级？
34. 如何验证 fail-closed 没有偷偷触发一次 retrieval recovery？

### 参考核验点

- 响应仍保持结构化，通常 `status=ok` 但 `action_decision=HUMAN_REVIEW`。
- 未通过自检的草稿不应作为最终事实答案发布。
- `claim_candidates` 应为空或不可发布。
- trace 应记录错误原因、动作决策和终态；非法 action 不得绕过安全门。

## 五、T3.4 多轮上下文与指代消解

### 基础题

35. Agent 如何解析“它有什么作用”中的“它”？
36. 为什么多轮对话中应优先选择最近一轮显式提到的对象？
37. 当前场景对象、历史显式对象和查询中明确对象发生冲突时，优先级如何确定？
38. 多个候选对象都可能匹配“这个部件”时，Agent 应直接回答还是先澄清？
39. 指代无法解析时，为什么不能把历史对话原文直接泄露到最终答案？
40. 危险输入与未解析指代同时出现时，安全门和上下文门哪个应先生效？

### 场景题

41. 用户先说“介绍座舱”，再说“解释起落架”，最后问“它有什么作用”，应解析到哪个对象？
42. 连续 20 组多轮对话均采用“先介绍座舱、再解释起落架、最后询问它”，应重点检查哪些字段？
43. 当前场景绑定到 `engine`，但最近一轮显式提到 `landing_gear`，跟随问题应如何解析？
44. 对话中没有任何可解析对象，用户问“它有哪些特点”，Agent 应返回什么类型的结果？

### 参考核验点

- `selected_object_id` 与 `query_object.target_component` 是否指向预期对象。
- reason code 是否为 `reference_strategy_most_recent_explicit` 或相应澄清原因。
- 不应把未确认的历史候选直接当作事实。
- 20 组样本应逐组可追踪，不能用单个样本代表整体覆盖率。

## 六、T3.5 Checkpoint 与故障恢复

### 基础题

45. 为什么 Agent 需要保存 checkpoint？
46. 检索后中断恢复时，如何避免重复执行已经完成的检索？
47. 请求指纹不匹配时，为什么必须拒绝直接恢复？
48. 终态 checkpoint 被重复提交时，系统应重新执行还是直接返回终态？
49. `max_resume_attempts=1` 的安全意义是什么？
50. checkpoint 清理失败是否应影响最终答案返回？应如何记录？
51. trace 和 checkpoint 为什么不能保存原始 prompt、私有记忆或敏感内容？

### 场景题

52. Agent 在 `EVIDENCE_READY` 后进程中断，恢复时应从哪个状态继续？
53. 恢复请求的 query 与原 checkpoint 指纹不一致，预期响应是什么？
54. Agent 已经进入 `FINAL_READY`，再次收到同一 run_id 请求时应如何处理？
55. 恢复过程中发现原始 prompt bundle 不完整，系统应继续拼接还是 fail-closed？
56. 如何用测试证明恢复后状态没有污染另一个 session 的 memory context？

### 参考核验点

- 恢复路径不重复已完成的检索、生成或自检动作。
- 不匹配请求在恢复前被拒绝。
- 终态恢复保持幂等，清理失败有告警但不泄露数据。
- checkpoint 中不应出现私有记忆、完整 prompt body 或敏感原文。

## 九、判定规则

- 只有最终答案正确而动作、证据或 trace 缺失时，不判定为通过。
- 触发安全降级并正确记录原因时，应按对应安全场景判定为通过。
- 真实 LLM 返回成功但生成内容未满足 claim 契约时，不得伪造为 `PASS`；应检查是否进入 `HUMAN_REVIEW`。
- 所有自动化结果应记录命令、环境、通过数、失败数和关键 trace 字段。

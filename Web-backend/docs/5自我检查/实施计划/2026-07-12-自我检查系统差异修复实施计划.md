# 自我检查系统差异修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Before editing code, use `using-git-worktrees`; for every failure use `systematic-debugging`; before each completion claim use `verification-before-completion`.

**Goal:** 将当前只校验 evidence ID 的 P5 原型重构为证据语义优先、可配置、可审计、可回退并覆盖语音输入/播报的自我检查质量闸门。

**Architecture:** 外部 AppPipeline、CLI 和公共响应保持稳定；内部改用单一 `SelfCheckInput`、强类型检查结果和配置化 `SelfCheckPolicy`。规则硬门控先执行，语义 judge 仅补充 claim 支持判断；所有动作由 `DecisionRouter` 根据八维 score card、issue code 和独立循环计数决定。回答重写从已验证 claim 重建，补检索通过结构化缺口改变检索计划，完整审计写入独立受控记录。

**Tech Stack:** Python 3.11+、标准库 `dataclasses`/`enum`/`typing.Protocol`/`re`/`json`、现有 `PromptRuntime`、`ModelClient`、`RetrievalController`、`ControlledRewriter`、pytest；不新增第三方依赖，不调用真实 Provider。

## 需要调用的 skill

按顺序使用：

1. `brainstorming`：在 G1 前确认 judge 不可用时的动作策略和 visual grounding 字段的兼容形式。
2. `using-git-worktrees`：创建 `codex/self-check-refactor` 隔离 worktree。
3. `subagent-driven-development`：逐 Task 实施；每个 Task 使用独立子智能体并完成两阶段审查。
4. `systematic-debugging`：红测、配置或回退循环失败时执行根因调查。
5. `requesting-code-review`：G1、G3、G6、G7 通过目标测试后发起审查。
6. `receiving-code-review`：核实评审意见后再修改。
7. `verification-before-completion`：每一项和最终门禁前运行本计划命令。

## Global Constraints

- 规格唯一来源是 `docs/5自我检查/设计文档/2026-07-12-自我检查系统差异修复任务.md`、项目总控 P0–P8 文档和原始 Word 第 9 章。
- 所有开发在隔离 worktree 中完成；不得覆盖当前共享工作区中的用户变更。
- `TextQueryRequest`、`TextQueryResponse.to_dict()` 顶层六键、CLI 参数、成功/失败退出码和既有 `ActionDecision` 字符串不得删除或改义。
- 航空事实只可由 reviewed 且 `usable_as_core_evidence=true` 的 `EvidencePackage` 支撑；记忆、Prompt、反馈和模型常识不能单独成为事实来源。
- 规则硬失败优先于语义 judge；judge 不能使无证据参数、危险操作、未审核来源或明确场景冲突通过。

- 不引入大型框架、真实生产数据库、真实外部服务、真实人工审核队列或密钥。
- 每个 Task 坚持红测先行、目标测试通过、前序回归通过、独立提交；失败不得带入后续 Task。

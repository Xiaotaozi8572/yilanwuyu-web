## 3. 专项定位和根因

当前实现已经有独立的 `src/self_check/` 目录，且 `AgentRuntime` 在 `ANSWER_DRAFTED` 后调用 `SelfCheckService`。这满足“自检是独立质量闸门”的骨架要求，但实现仍停留在只检查 ID 与少量关键词的规则原型，不能作为设计文档定义的可审计质量裁决层。

已确认的根因级差异如下：

1. `ClaimExtractor` 只复制 `AnswerEnvelope.claim_candidates`，没有从 `short_answer`、`main_answer`、展示块和语音文本中补全最小 claim；未声明的事实会直接漏检。
2. `EvidenceAligner` 只验证 `evidence_id` 存在，不比较 claim 与证据内容；没有 `partially_supported`、`contradicted` 和 required-evidence-type 判定。
3. 自检不消费 `gate_status`、`missing_evidence`、`retrieval_plan` 或冲突信息，无法完成 CRAG 式检索充分性判断。
4. score card 缺少证据覆盖、检索充分性、多模态一致性、学习者适配和表达清晰度；已声明的阈值未参与路由，且未配置化。
5. 场景检查依赖硬编码的三个部件词；多模态检查只确认布局字段存在；两者没有处理 aircraft、热点、视角、候选对象、文本交叉验证或歧义。
6. `memory_context`、`prompt_asset` 在自检签名中却没有被消费，`aviation_self_check` Prompt 资产也没有运行时调用。
7. 教学适配、不确定性表达、Policy memory 和语音专属检查均未形成自检结果。
8. `HUMAN_REVIEW` 从不产生；场景明确错配与场景不明被混为 `ASK_CLARIFICATION`；`REWRITE_ONLY` 删除 metadata 却可能保留原始未支持文本。
9. audit log 缺少运行上下文、证据、分数、前后答案、原因和时间戳；公共 trace 只保存 `check_report_id`。
10. 旧 `DecisionPolicy` 默认阈值、`COMPONENT_TERMS`、关键词安全列表和 `app.max_state_loop` 构成了 YAML 未消费或规则硬编码的双轨状态。

## 4. 目标架构与不可突破的边界

### 4.1 目标数据流

```text
SelfCheckInput
  = run_id + user_query + AnswerEnvelope + EvidencePackage
  + SceneState + MemoryContext + generation_prompt_provenance
  + SafetyPolicyContext + CheckLoopState + optional VoiceCheckContext

文本 claim 完整抽取
  -> 规则硬门控（来源、参数、安全、场景、循环）
  -> 语义支持判定与检索充分性评估
  -> 场景 / 多模态 / 边界 / 教学 / 语音检查
  -> 八维 ScoreCard + IssueList
  -> DecisionRouter
  -> PASS | REWRITE_ONLY | RETRIEVE_MORE | ASK_CLARIFICATION
     | HUMAN_REVIEW | SAFE_RESPONSE | STOP
  -> 可脱敏 Trace 摘要 + 受控 SelfCheckAuditRecord
```

### 4.2 设计决定

- `EvidencePackage` 是唯一航空事实来源。记忆、Prompt、用户反馈、模型常识和视觉检索结果只有在被已审核证据文本交叉支持时才可支撑事实。
- 自检用规则完成可确定的失败；`SemanticJudge` 只判断 claim 与候选证据的语义关系，不能覆盖任何规则硬失败。
- 不新增 LangGraph、LangChain、Ragas、DeepEval、Guardrails、向量数据库或真实外部服务依赖。语义 judge 使用现有 `ModelClient`、`PromptRuntime` 和 `typing.Protocol`；离线测试使用显式 fake judge。
- judge 不可用时，不把未知语义支持误判为 `supported`。高风险或存在冲突的 claim 进入 `HUMAN_REVIEW`；低风险开放式解释输出不确定性说明或 `RETRIEVE_MORE`，规则确定支持的 claim 可正常通过。
- 自检专用配置放入 `configs/self_check.yaml`，由统一 settings loader 加载。删除未消费的 `app.max_state_loop`，不再把 P5 阈值、循环或部件/安全规则写死在 Python 常量中。
- `REWRITE_ONLY` 必须从已验证的 claim 和 source binding 重建答案，不能只删除 claim metadata 或在原文末尾追加说明。
- `RETRIEVE_MORE` 必须输出结构化 `retrieval_requirements`，由检索控制器生成新的查询/过滤条件，不能无变化重复原计划。
- 普通 trace 仅保存摘要、ID 与动作；包含 before/after answer 的完整审计记录由权限受控的 audit store 保存，不能混入 Prompt 正文、原始私人记忆、密钥或原始音频。

### 4.3 外部兼容和非目标

- 保持 `ActionDecision` 的既有字符串：`PASS`、`REWRITE_ONLY`、`RETRIEVE_MORE`、`ASK_CLARIFICATION`、`HUMAN_REVIEW`、`SAFE_RESPONSE`、`STOP`。
- 保持 `TextQueryResponse.to_dict()` 的六个顶层键不变；可在 `trace` 中附加脱敏后的 `self_check_summary`。
- 保持 `AnswerEnvelope` 当前字段可反序列化；内部 claim 与检查结果改用强类型对象后在边界序列化为兼容字典。
- 本专项不接入真实人工审核队列、不改造知识入库、不新增 HTTP endpoint、不连接真实模型、数据库或密钥。`HUMAN_REVIEW` 在当前离线模式下生成可审计的保守终态并保留 review request。

## 6. 统一验收矩阵

| 编号 | 场景 | 必须结果 |
| --- | --- | --- |
| SC-01 | 正文含未声明的参数 claim | 抽取该 claim，判定 `unsupported`，高风险进入 `RETRIEVE_MORE`。 |
| SC-02 | claim 绑定存在但语义无关的 evidence ID | 不得为 `supported`；进入 `unsupported` 或 `contradicted`。 |
| SC-03 | 部分证据支持且缺少限定条件 | `partially_supported`，改写指令保留支持范围并补不确定性。 |
| SC-04 | 两个已审核来源相互冲突 | `contradicted`，触发 `HUMAN_REVIEW`。 |
| SC-05 | 证据覆盖不足且有明确缺口 | `RETRIEVE_MORE`，带有可消费的 `RetrievalRequirement`。 |
| SC-06 | 场景已选机翼、答案解释发动机 | `REWRITE_ONLY` 或 `RETRIEVE_MORE`，不得笼统追问。 |
| SC-07 | 多个候选热点且指代为“这个” | `ASK_CLARIFICATION`。 |
| SC-08 | 图像标签/方向与正文冲突 | 多模态失败，不得 PASS。 |
| SC-09 | 记忆或 Prompt 被表述为航空事实 | `REWRITE_ONLY`，删除或降级该 claim。 |
| SC-10 | 初学者收到术语堆砌 | learner/clarity 低分，`REWRITE_ONLY`，证据绑定保留。 |
| SC-11 | 危险维修/改装/规避流程请求 | `SAFE_RESPONSE`，不携带可执行细节。 |
| SC-12 | 一条支持、一条不支持的混合答案 | 重写后正文只保留支持 claim，未支持句不出现。 |
| SC-13 | 低置信 ASR、术语错误、语音指代不明 | 在检索前 `ASK_CLARIFICATION` 并记录语音审计。 |
| SC-14 | 语音文本超长或 TTS 已被打断 | 在播报前压缩或停止旧播报并进入反馈/澄清状态。 |
| SC-15 | judge 不可用且高风险语义无法确认 | `HUMAN_REVIEW`，不降级为 PASS。 |

## 7. 停止条件

严格执行 `AGENTS.md` 的停止条件；此外出现以下情况必须停止并在 `docs/项目总控/STATUS.md` 记录“待确认”：

- `aviation_self_check` 所需的结构化输出无法由现有 `ModelClient` 表达，且必须新增大型依赖。
- 上游 `EvidencePackage` 缺少实现图文交叉验证所需的对象标签、位置或视角字段，且补齐字段会改变 P3 外部契约。
- 将 `HUMAN_REVIEW` 连接到真实人员、消息队列或生产系统。
- 现有公开 API 无法以向后兼容方式携带审计摘要或 review request。

## 项目定位（30 秒）

航空科普场景的证据驱动智能导师。系统按 P0–P8 分阶段建成"输入理解 → 记忆 → RAG 证据检索 → 回答生成 → 自检 → 反馈改写 → 语音交互 → 评测与部署治理"全链路，现支持真实语音（faster-whisper 本地 ASR + edge-tts TTS）；无密钥环境自动降级 mock，保证答辩现场可完整演示。

### 2.1 离线一键演示（T14 兜底路径）

`scripts\demo_offline.py` 一条命令跑通"检索 → 证据门 → 自检 → 产出"全链路，强制全 mock（LLM/Embedding 为 MockModelClient / MockEmbeddingProvider，纯文本路径不加载语音模块），脚本不读取任何 API 密钥环境变量，可断网运行：

```bash
.venv\Scripts\python.exe scripts\demo_offline.py
# Git Bash 下可显式清空密钥再跑（可选）：
env -u DEEPSEEK_API_KEY -u DASHSCOPE_API_KEY -u NVIDIA_API_KEY .venv/Scripts/python.exe scripts/demo_offline.py
```

三个演示案例：① 正常事实问答（输出证据包 ID、证据 ID 与 claim→evidence 引用）；② 证据不足问题触发拒答（无证据时不编造，澄清而非给数值）；③ 用户反馈"简单点"触发 SIMPLIFY 改写（保留证据锁定与引用）。每个案例打印阶段轨迹与关键证据 ID，全部通过时退出码 0。

## 三、环境预检清单

1. **虚拟环境**：使用项目 `.venv`（Python 3.11.9，实测）；Python 版本统一 3.11；依赖同步 `uv sync --frozen --group dev`；禁止全局 Python。
2. **密钥环境变量**（`.env.example` 不会被自动加载，须手动 set/export）：`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`、`DASHSCOPE_API_KEY`、`NVIDIA_API_KEY`。
3. **模型下载**：预缓存于 `%USERPROFILE%\.cache\huggingface\hub`。Embedding 模型 `BAAI/bge-m3` 需提前下载（`huggingface-cli download BAAI/bge-m3`）；faster-whisper 模型（如 `Systran/faster-whisper-small`）首次运行自动下载，建议提前预缓存避免现场等待。
4. **VC++ 运行库**：Windows 需安装 Microsoft Visual C++ Redistributable（faster-whisper / ctranslate2 依赖），缺失会导致语音组件启动失败。
5. **部署校验**：`scripts\validate_deployment.py --profile mock`（离线门禁，须通过）；真实环境用 `--profile real` 检查密钥存在性、provider 真实配置、模型路径与 ASR/TTS 可达性（5 秒超时探测）。

## 四、记忆系统现状（T32 口径）

记忆系统当前运行后端为本地 SQLite（`configs/memory.yaml` `backend: local`）；Java memory-service（PostgreSQL+pgvector，含加密/遗忘/图投影）已完成 M0–M5 开发与契约测试，定位为**权威化演进设计**，通过 AuthorityMode 状态机灰度切换（LOCAL → SHADOW → CUTOVER_PREPARED → REMOTE），当前处于 **LOCAL 阶段**，未切流。答辩表述一律以此为准；切换待灰度（见 `docs/评测与验收/release_acceptance.md` 已知缺口表）。

**记忆遗忘口径（T31 声明）**：遗忘能力在 Java 权威侧就绪、待切流——当前 LOCAL 阶段 Python 侧不提供本地删除接口，遗忘治理入口随 REMOTE 切流后在权威侧统一提供；在切流前答辩表述为"遗忘能力随 Java 记忆服务切流后开放"，不得表述为本地已支持遗忘。

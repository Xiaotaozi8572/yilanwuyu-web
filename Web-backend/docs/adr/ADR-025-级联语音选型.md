# ADR-025 语音链路采用"级联"选型（ASR → 文本问答 → 文本投影 → TTS）

> 状态：已接受（2026-08-15，T28）。
> 关联：`docs/合规与隐私边界.md`（许可与隐私边界）、`docs/评委速览.md`（答辩速览）。口径与 T26 一致：不宣称多模态通道与数字人已启用（`configs/rag.yaml` 中 scene/visual/graph 通道 `enabled:false`，属协议预留；数字人为"协议已定义，3D 端 SDK 对接为下一阶段"）。

## 背景：实时性 vs 可信性冲突

语音交互的两种诉求在本项目场景（航空科普答疑，未成年人为主）中直接冲突：

- **实时性**：端到端语音大模型（GPT-4o Realtime / Qwen-Omni）可把"听懂即答"的延迟压到最低，且天然带说话人风格与多模态表达；
- **可信性**：本项目回答必须可追溯（证据包 ID、证据 ID、claim→evidence 引用、自检报告与审计留痕）。端到端模型的音频生成流是一个黑盒流，**无法在流内插入"检索证据 → 证据门 → 自检 → 审计"的确定性环节**；其输出也无法与既定证据链绑定。

两者不可兼得时，本项目选可信性优先：语音只是入口与出口，决策与事实链必须留在可审计的文本流水线内。

## 备选方案

| 方案 | 实时性 | 可插入证据链/自检/审计 | 合规面 | 结论 |
|---|---|---|---|---|
| A. GPT-4o Realtime（端到端） | 最优 | 不可行（音频流黑盒） | 用户原始语音直接送外部服务 | 否决 |
| B. Qwen-Omni（开源端到端多模态） | 优 | 不可行（同 A） | 可本地化，但多模态通道属协议预留（T26 口径） | 否决 |
| C. **级联**：faster-whisper 本地 ASR → 文本检索问答 → SpokenAnswer 文本投影 → edge-tts TTS | 可接受（见代价与缓解） | **可行**：全程复用 P0–P8 证据链 | 出境文本仅答案口语投影（见合规文档②） | **采纳** |

## 决策与论据

**决策：语音链路采用级联选型（方案 C）**，即 `configs/voice.yaml` 现状：`asr_provider: whisper`（本地推理）+ `tts_provider: edge`（公共端点 TTS），中间为既有文本流水线（P0–P8：输入理解 → RAG 证据检索 → 回答生成 → 自检 → 反馈改写）。

论据（为什么端到端模型不能替代）：

1. **可信是本项目护城河**：答辩与验收的核心证据是"回答有证据、可追溯、经自检"。级联把语音边界压缩为两端文本（输入文本化、输出文本投影），中间每一环（`spoken_answer.py` 的口语投影只允许从受支持句子选取且安全句必须保留、`edge_tts.py` 强制 `source_evidence_package_id` 证据溯源、`orchestrator.py` 的 `_trusted_final_answer` 信任门）都在既定接口内可审计；
2. **端到端模型无法插入确定性门禁**：音频流内无法放置证据门与自检报告，其输出无法与证据包绑定，等于放弃项目核心能力；
3. **合规面更小**：端到端方案把用户原始语音直接送外部模型；级联方案出境文本仅为答案口语投影（`docs/合规与隐私边界.md` ② 节，实证：`edge_tts.py:86-96` 仅拼接 answer_brief/spoken_steps/follow_up_prompt）。

## 代价与缓解

| 代价 | 缓解 |
|---|---|
| 交互感弱于 Realtime（无半句话响应、无情感/多模态表达） | 已实现打断（barge-in，`voice.yaml:22-23` `barge_in_enabled: true`）；多模态/数字人按 T26 口径如实标注为协议预留，不宣称已启用 |
| 首响延迟预算高于端到端 | **延迟预算叙事**：本地 ASR（无网络往返）+ 文本流水线（单轮检索/生成）+ 流式 TTS 分块播放（`tts.py` chunk_delay_seconds 可调、`edge_tts.py` 逐段合成即送）；语音预算硬约束 20 秒/180 字符（`voice.yaml:13-15`）保证播放时长可控；真实首响延迟指标（T13 麦克风实测）在 `docs/评委速览.md` 1.2 表待回填，答辩不宣称未达标量化成绩 |
| edge-tts 公共端点不可用 | 统一降级 `display_answer_only`（文本展示 + CLARIFY，双阶段降级详见 `docs/合规与隐私边界.md` ③ 节） |
| 许可证边界 | 实证 edge-tts 6.1.19 为 LGPL-3.0，直接 import 不触发传染（详见 `docs/合规与隐私边界.md` ① 节）；若未来打包分发再按 ① 节边界条件评估 |

**演进保留**：端到端模型保留为未来候选，评估前置条件为"能在生成流内插入确定性证据校验与审计"；在当前架构下不引入端到端依赖。

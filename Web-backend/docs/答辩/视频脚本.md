# 答辩演示视频脚本 — 3 分钟真实链路演示

> 任务：T33 答辩材料制作。本脚本为 3 分钟演示视频分镜（真实链路为主，含 T14 离线兜底切换点标注）。
> 口径约束：对照 T26——不展示/不宣称未启用能力（多模态、数字人、NLI 语义判定）；
> 语音实测数字未回填前不读任何量化成绩（T13）。
> 关联：`docs/答辩/PPT大纲.md`、`docs/答辩/讲稿.md`、`docs/答辩/现场预检清单.md`（T35）。

## 分镜总览（总时长 ≈ 180 秒）

| 镜头 | 时间 | 内容 | 演示路径 |
|---|---|---|---|
| S1 | 0:00–0:20 | 开场：项目定位一句话 + 演示目标声明 | 无（字幕） |
| S2 | 0:20–0:50 | 真实链路：语音问答"解释一下升力" | 真实链路（run_voice.py + run_frontend.py） |

## S1 开场（0:00–0:20，20 秒）

- 画面：项目封面 + 标题"翼览无余：回答有证据、可追溯、经自检的航空科普智能导师"。
- 旁白：大家好，这是我们项目的三分钟演示。演示目标是展示一条**真实的问答链路**：
  从语音提问，到证据检索与门控，到回答生成与自检，再到反馈改写，全程可审计。
  演示中出现的所有数字均来自项目实测记录；语音实测指标因待人工回填，本视频不宣读。
- 口径提示：此时不出现任何量化语音指标。

## S2 真实链路：语音问答（0:20–0:50，30 秒）

- 画面：终端启动 `scripts/run_voice.py`（显示 `listening on ws://127.0.0.1:<port>`）
  → 启动 `scripts/run_frontend.py` → 浏览器打开 `http://127.0.0.1:8000/index.html`
  并授权麦克风 → 对着麦克风提问"解释一下升力"。
- 旁白：第一段，真实语音问答。语音识别由本地的 faster-whisper 完成，识别文本进入
  **文本问答流水线**——查询理解、知识库检索、证据门判定、回答生成、自检，最终答案
  再经 edge-tts 合成为语音播报。请大家注意：语音只是入口和出口，中间的每一环
  都走的是与文本完全相同的证据链，这就是我们"级联语音"的设计——语音两端文本化，
  事实链全程可审计。
- 画面注记：若现场/录制环境无麦克风或 TTS 端点不可用，本镜头切换到 T14 离线兜底
  （见"离线兜底切换点"），用 CLI 文本问答代替语音，并在字幕注明。

### 离线兜底切换点 A（S2/S3 语音不可用时）

- 命令：`scripts\demo_offline.py`（T14 兜底脚本，强制全 mock、不读密钥、可断网）；
  或 `python -m app.cli --query "解释一下升力"`（CLI 文本问答）。
- 切换条件：麦克风不可用 / faster-whisper 模型未预下载 / edge-tts 端点不可达 /
  VC++ 运行库未修复导致 onnxruntime 加载失败。
- 切换口径：字幕声明"当前为离线兜底演示（T14），真实语音链路见实测回填后视频"，
  不把 mock 演示表述为真实语音能力。

## S3 追问与证据链展示（0:50–1:15，25 秒）

- 画面：同一会话追问"它和普通机翼有什么区别？"（指代消解，"它"= 上一轮讨论对象），
  随后切换到 CLI/trace 视图展示：检索计划、命中的证据包 ID 与证据 ID、
  claim→evidence 引用映射、证据门状态。
- 旁白：第二段，同会话追问与证据链展示。系统能正确消解"它"的指代，因为记忆上下文
  只影响个性化表达，事实本身依然来自证据包。我们切到审计视图：大家可以看到
  回答里的每一条主张，都对应着具体的证据 ID 和审核状态——这就是"可追溯"。
  检索融合当前启用四个通道，多路结果经过 RRF 融合与重排序后，由证据门给出四态判定。

## S4 fail-closed 拒答（1:15–1:40，25 秒）

- 画面：输入一个知识库未覆盖/无权威证据的问题（评测集外的域外题或无来源的参数问题，
  录制时从 `docs/评测与验收/评测报告/rag_100q_bench_report.md` 的 weak 题表中选择并核对），
  展示系统输出：不编造数值，返回澄清/资料不足说明，trace 中 `evidence_gate=weak`、
  `missing=no_qualified_evidence`。
- 旁白：第三段，本项目的核心行为——**fail-closed**。这个问题在知识库里没有
  已审核的权威证据，系统不会给出"听起来合理"的数字，而是明确告知资料不足并澄清。
  我们 100 题独立复核的结果是：被证据门放行的回答误拦率 0%，被拦下的弱证据
  漏拦率 0%。保守，并且保守得有理有据。

## S5 反馈改写（1:40–2:05，25 秒）

- 画面：在语音播报中或回答后输入"讲简单点"（语音演示为 barge-in 打断），
  展示改写后答案：术语密度降低，但 source_binding 与证据引用保持不变
  （展示改写前后 delta 对比）。
- 旁白：第四段，反馈改写。用户反馈"讲简单点"，系统在**证据锁定**的前提下
  做表达层面改写，来源引用一条不少；如果用户质疑的是事实本身，系统不会直接改口，
  而是先补检索再回答。每一轮改写都有 delta 记录，可审计。

## S6 审计与门禁（2:05–2:30，25 秒）

- 画面：依次运行并截屏：
  1. `pytest tests/ -q` → 1500 collected / 0 failed；
  2. `scripts\run_eval.py --suite text_smoke` → case_count=2 / passed_count=2 / pass_rate=1.0；
  3. `scripts\export_trace_report.py --run-id <demo>` 导出本轮 trace 报告。
- 旁白：最后，工程门禁。全量自动化测试 1500 个用例零失败；离线评测三案例全通过；
  刚才的每一轮演示都导出了可审计的运行追踪。检索侧，90 题评测集上融合召回率 0.9889、
  Recall@3 0.70、MRR 0.6173，复核可复现；可信度侧，faithfulness 4.94 分。
  这些数字都来自 `docs/评测与验收/` 下的实测报告，可以随时查阅。

## S7 收尾（2:30–3:00，30 秒）

- 画面：合规三要点 + 演进路线图（PPT P8/P9 同款）逐条浮现。
- 旁白：最后是三句话。合规上：TTS 组件实证 LGPL-3.0 许可无传染；出境文本仅限答案
  口语投影，不含用户转写与语音；未成年人场景默认不落盘、记忆默认不授权。
  演进上：短期完成语音实测回填与现场预检彩排，中期推进数字人 SDK 对接与多模态
  按需启用——这些是下一阶段工作，今天不做任何超前宣称。
  谢谢观看，欢迎提问。

## 录制与检查要求

1. 录制前按 `docs/答辩/现场预检清单.md`（T35）逐项预检：VC++ 运行库（onnxruntime 可加载）、
   faster-whisper/BGE-M3 模型预下载、密钥环境变量注入、电量/网络/投屏预案。
2. 全程不得出现密钥、Authorization 头、真实生产地址；日志窗口如有敏感输出需遮挡。
3. 若真实链路任一环节失败，按"离线兜底切换点 A"切换并字幕注明，不得用 mock 冒充真实。
4. 语音实测（T13）回填后，可在 S2/S3 补录真实首响延迟数据镜头并更新旁白数字；
   未回填前保持现状。
5. 视频总时长控制在 3 分钟 ±15 秒；逐镜头核对与 `docs/答辩/PPT大纲.md`、`docs/答辩/讲稿.md` 表述一致
   （不得出现超出 T26 口径的能力宣称）。

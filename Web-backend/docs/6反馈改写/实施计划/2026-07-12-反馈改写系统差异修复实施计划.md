# 反馈改写系统差异修复实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or inline execution with review checkpoints to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 P6 反馈改写重构为可由文本与语音正式入口触发、保留并核验证据、能够回退到 P3/P5、且只经 P2 治理写入稳定偏好的可审计闭环。

**Architecture:** 使用 `FeedbackRewriteService` 作为唯一 P6 编排入口。该服务从持久化 checkpoint 恢复上一轮已通过 P5 的答案与证据，按反馈动作选择局部改写、补检索、场景澄清、安全回复或偏好候选，并在最终输出前强制经过 evidence lock 和 P5。P3、P5、P2、语音和 CLI/API 仅通过显式契约接入该服务，不保留第二条手工拼装路径。

**Tech Stack:** Python 3.13、标准库 `sqlite3`、dataclasses、现有 Mock/ModelClient、PromptRuntime、pytest；不新增第三方依赖，不调用真实 Provider、生产数据库或外部服务。

## Global Constraints

- 全部代码修改在独立 `codex/feedback-rewrite-refactor` worktree 中完成；不得覆盖当前共享工作区的未提交变更。
- 每次 Python/pytest 命令前先执行：`$env:PYTHONPATH = (Join-Path (Get-Location) 'src')`，避免虚拟环境中其他 worktree 的包路径覆盖当前源码。
- 航空事实只能来自 `reviewed` 且 `usable_as_core_evidence=true` 的 `EvidencePackage` 条目；用户反馈、记忆、Prompt 和模型常识不得构成事实来源。
- 不改变 `TextQueryRequest`、`TextQueryResponse.to_dict()`、既有文本 CLI 参数、既有 `ActionDecision` 字符串或已发布 answer 字段的语义；反馈能力通过新增 request/response 和新增 CLI 参数暴露。
- `feedback.max_rewrite_rounds`、`feedback.allowed_format_transforms`、`feedback.preference_stability_threshold`、`feedback.preference_window_days`、`feedback.checkpoint_ttl_seconds`、`feedback.safety_sensitive_patterns` 必须只在 `configs/feedback.yaml` 定义并被运行时消费。
- `SAFE_RESPONSE` 不能包含可执行维修、拆卸、改装、故障处置、飞行操作或规避步骤；`HUMAN_REVIEW` 在离线模式只能输出保守的可审计答复，不连接真实人工系统。
- 每个工作包遵守 `docs/项目总控/harness.md` 对 P2、P3、P5、P6、P7 和 P8 的边界；任何需要破坏 P3/P5 外部接口的情况必须停止，并在 `STATUS.md` 记录“待确认”。
- 删除旧符号前必须先迁移调用方、运行 `rg` 证明零引用、通过目标测试与全量测试；不得长期保留新旧双链路。

## 实施前文件地图

| 路径 | 完成后的职责 |
| --- | --- |
| `configs/feedback.yaml` | P6 的唯一策略、轮数、格式、稳定性、checkpoint 生命周期和安全模式来源。 |
| `src/feedback/contracts.py` | `FeedbackRewriteRequest`、`FeedbackRewriteResponse`、checkpoint 查找状态、目标维度、检索请求与重写结果的内部类型。 |
| `src/feedback/policy.py` | 严格加载 `feedback.yaml`，不提供与 YAML 竞争的业务默认值。 |
| `src/feedback/checkpoint_store.py` | 基于标准库 SQLite 的保存、读取、归属校验、过期检查与轮数推进。 |
| `src/feedback/parser.py` | 配置化解析 canonical intent、目标 span、目标维度、格式、核查查询和偏好信号。 |
| `src/feedback/decision_router.py` | 将解析结果和 checkpoint 状态转换为八类 `ActionDecision` 及 P6 执行分支。 |
| `src/feedback/evidence_lock.py` | 从合格证据建立锁，验证每个答案 span/claim/source binding，失败关闭。 |
| `src/feedback/claim_rebuilder.py` | 将改写后的可断言 span 重新映射为 claim candidates 与 source bindings。 |
| `src/feedback/rewriter.py` | 使用 `aviation_feedback_rewrite` prompt bundle 和受控 fallback 生成完整 `AnswerEnvelope` 草稿。 |
| `src/feedback/delta_map.py` | 生成 claim/span 级的 preserved/rewritten/removed/added/hedged 差异。 |
| `src/feedback/service.py` | P6 唯一编排服务；接线 P3、P5、P2、runtime、trace 和终态。 |
| `src/agent/runtime.py` | 文本终态写 checkpoint；新增 `run_feedback` 并合法驱动状态机。 |
| `src/services/app_pipeline.py` | 暴露 `run_feedback`，复用与文本链一致的依赖实例。 |
| `src/app/api/schemas.py`、`src/app/cli.py` | 反馈请求/响应和 CLI 适配，保持旧文本模式兼容。 |
| `src/knowledge/retrieval_controller.py` | 只新增从 verification query / scene rebinding 生成正式 `RetrievalPlan` 的适配方法。 |
| `src/self_check/*` | 只补充 P6 必需的正文/claim 一致性检查和改写后调用；P5 保持唯一质量裁决者。 |
| `src/memory/repository.py`、`src/memory/controller.py` | 只提供稳定性计数与候选提交所需接口；不让 P6 直接写 ACTIVE 记忆。 |
| `src/voice/*` | 先停止播报，将打断转为 canonical feedback request，再调用 `AppPipeline.run_feedback`。 |

**执行顺序说明：** 下文的 Task 编号是实际执行顺序；F 编号用于与任务文档中的工作包追踪对应。为避免 runtime 依赖未完成的解析与改写实现，F3、F4 在执行顺序上先于 F2；任务文档已经将 F2 的依赖明确为 F1、F3、F4。

# 记忆系统重构设计文档

## 1. 目标

本设计用于修复当前代码中的记忆系统与《翼览无余智能体模块设计文档V2_增加语音交互.docx》之间的差异。目标不是在现有 MVP 上补几个判断条件，而是把 `src/memory` 重构为一个分层、持久化、可检索、可治理、可审计，并真实接入 Agent 主链路的记忆系统。

重构后的记忆系统必须满足四个核心判断：

1. 系统真的能从交互事件中沉淀稳定记忆，而不是只保存测试用的内存对象。
2. 系统真的能在回答前检索并构造 `memory_context`，而不是在主链路中创建空上下文。
3. 记忆只能影响表达方式、指代解析、教学路径和误解纠偏，不能成为航空事实来源。
4. 所有记忆读写都可解释、可审计、可删除、可降权、可过期、可替代。

## 3. 当前问题归纳

当前实现已经具备一部分正确的基础原则，但没有达到完整方案要求。

已实现且应保留的原则：

- 定义了 `candidate`、`active`、`stale`、`superseded`、`expired`、`rejected`、`archived` 等状态。
- 定义了事件、候选记忆、结构化记忆、写入结果和维护报告。
- 记忆写入需要先有事件。
- 低置信、高隐私、航空事实候选会被拒绝。
- 冲突偏好可以用 `supersedes/superseded_by` 表示。
- `memory_context` 明确声明不能作为航空事实证据。

必须修复的问题：

- `AgentRuntime` 当前直接创建空 `MemoryContext()`，没有调用 `MemoryController.build_memory_context()`。
- 当前存储是内存字典，不具备长期记忆能力。
- 当前没有 L4 向量语义记忆、L5 时间图谱、L8 审计展示。
- 当前没有真正的记忆检索排序，只是线性扫描后取前 N 条。
- 当前 `policy_memory` 参数没有实际治理作用。
- 当前 `configs/memory.yaml` 没有被记忆系统作为运行配置加载。
- 当前反馈模块生成 `memory_update_candidate` 后没有进入记忆治理流程。
- 当前记忆接口 `upsert_memory` 语义过于直接，容易绕过“事件 -> 候选 -> 治理 -> 分层存储”的设计。
- 当前测试主要验证 MVP 行为，不能证明主链路真实使用记忆。

## 4. 重构原则

### 4.1 不做补丁

不得只在现有 `MemoryController` 中增加零散条件。现有内存 MVP 应被重构为清晰的分层模块。

### 4.2 不保留双路径

重构完成后，生产代码中不能同时存在“旧内存 store 路径”和“新持久化路径”。测试可以使用临时数据库，但不能让生产代码在配置缺失时静默回退到旧内存实现。

### 4.3 不留下冗余接口

删除或替换以下接口语义：

- `InMemoryEventLog`
- `InMemoryMemoryStore`
- 暴露给外部直接写长期记忆的 `upsert_memory`
- 不被调用的 `policy_memory` 参数
- 只为兼容旧测试存在的旧字段或旧 helper

### 4.4 事实边界不可变

航空事实只能来自 `evidence_package`。记忆不能作为 `EvidenceItem`，不能写入 `knowledge/source_registry.py`，不能改变事实 claim 的结论。

### 4.5 主链路必须真实使用记忆

`AgentRuntime` 必须接收 `MemoryController`，在 P1 之后、P3 检索之前构造真实 `MemoryContext`。如果记忆系统不可用，应显式报错并阻止本轮进入事实生成链路，不能悄悄创建空上下文冒充成功。

## 5. 目标分层架构

重构后的系统按参考文档 L0-L8 收口。

| 层级 | 职责 | 落地模块 |
| --- | --- | --- |
| L0 多模态采集 | 接收文本、语音、点击、测验、反馈、场景输入 | 由 `input`、`voice`、`feedback` 生成事件，不在 `memory` 中直接采集硬件 |
| L1 事件日志 | 持久保存原始交互事件 | `memory.repository.MemoryRepository.record_event` |
| L2 热状态 | 保存当前会话、场景、讲解进度 | `MemoryContextBuilder` 从事件、scene_state、session scope 聚合 |
| L3 结构化记忆 | 学习者画像、偏好、误解、掌握度、授权 | `StructuredMemory` + SQLite 表 |
| L4 向量语义记忆 | 会话摘要、反思、长文本经验、Prompt 候选 | `semantic_index.py` |
| L5 时间图谱 | 用户、概念、误解、场景、记忆之间的时间关系 | `memory_relations` 表 + `temporal.py` |
| L6 记忆控制 | 读写编排、检索路由、上下文预算 | `controller.py` + `retrieval.py` |
| L7 维护治理 | 去重、合并、衰减、过期、删除、归档 | `governance.py` + `consolidation.py` |
| L8 审计展示 | 读写原因、命中记录、报告导出 | `audit.py` |

## 6. 新文件结构

重构后 `src/memory` 应为：

```text
src/memory/
  __init__.py
  schemas.py
  repository.py
  extractor.py
  temporal.py
  conflict.py
  consolidation.py
  governance.py
  semantic_index.py
  retrieval.py
  context.py
  audit.py
  controller.py
```

每个文件的职责如下：

- `schemas.py`：只定义数据对象和枚举，不包含流程逻辑。
- `repository.py`：SQLite 持久化实现，负责事件、结构化记忆、语义条目、关系和审计日志。
- `extractor.py`：从事件中生成候选记忆，不负责写入。
- `temporal.py`：时间解析、过期、stale、衰减和时间关系辅助。
- `conflict.py`：检测重复、替代、矛盾和事实污染风险。
- `consolidation.py`：合并、确认、替代、归档、降权。
- `governance.py`：隐私、授权、安全、事实隔离和写入权限。
- `semantic_index.py`：管理长文本记忆的 embedding 写入和检索。
- `retrieval.py`：根据 query、scene、task_type 和权限检索记忆并打分。
- `context.py`：把检索命中转换为 `MemoryContext`。
- `audit.py`：读写审计和可解释报告。
- `controller.py`：唯一公开编排入口。

## 8. 持久化方案

使用 SQLite 作为当前正确落地方案。

原因：

- 项目尚未确认生产数据库，不能引入大型外部依赖。
- SQLite 是 Python 标准库可用能力，适合本地演示、审计、测试和后续迁移。
- 相比内存字典，SQLite 能提供真实持久化、事务和可检查的数据表。
- 后续迁移到 PostgreSQL、Qdrant、Milvus 或图数据库时，可以通过 repository 接口替换，不影响上层模块。

数据库文件位置由配置决定：

```yaml
memory:
  store:
    provider: sqlite
    path: data/processed/memory.sqlite3
```

如果配置缺失，系统应抛出明确配置错误。不能静默使用内存存储。

SQLite 表：

- `interaction_events`
- `memory_candidates`
- `structured_memories`
- `memory_relations`
- `semantic_memory_entries`
- `memory_audit_logs`
- `memory_context_runs`

## 9. 写入流程

所有长期写入必须经过 `MemoryController`，流程固定为：

1. `record_event(event)`：写入 `interaction_events`。
2. `extract_candidates(event_id)`：从事件中抽取候选。
3. `normalize_temporal(candidate)`：补齐时间字段。
4. `detect_conflicts(candidate)`：检测重复、替代、矛盾。
5. `consolidate(candidate, conflicts)`：合并、确认、替代或归档。
6. `governance_check(candidate)`：检查隐私、授权、事实隔离、安全边界。
7. `commit_memory(candidate)`：写入结构化库、语义索引、时间关系。
8. `record_audit(decision)`：记录写入或拒绝原因。

外部公开接口：

```python
record_event(event: InteractionEvent) -> str
process_event(event_id: str) -> MemoryProcessingReport
submit_candidate(candidate: MemoryCandidate) -> MemoryProcessingReport
build_memory_context(request: MemoryRetrievalRequest) -> MemoryContext
run_maintenance(job: MemoryMaintenanceJob) -> MemoryMaintenanceReport
```

不再对外暴露 `upsert_memory(candidate)`。

## 10. 检索排序设计

回答前记忆检索不允许线性取前 N 条。必须使用记忆检索请求：

```python
MemoryRetrievalRequest(
    user_id: str | None,
    session_id: str | None,
    query_text: str,
    task_type: str,
    scene_state: SceneState | None,
    budget: int,
)
```

排序公式：

```text
memory_score =
  semantic_relevance
  + scope_match
  + scene_match
  + confidence
  + stability
  + recency_bonus
  + explicit_confirmation_bonus
  - expiry_penalty
  - conflict_penalty
  - privacy_penalty
```

得分维度必须写入 `score_breakdown`，用于审计展示。

筛选规则：

- `expired`、`rejected`、`archived` 默认进入 `prohibited`。
- `superseded` 默认进入 `prohibited`，除非审计报告需要解释为什么不用旧记忆。
- `stale` 可以进入 `optional`，但必须有 `temporal_notes` 提醒需要复核。
- 高隐私记忆默认进入 `prohibited`，除非当前任务明确需要且 `policy_memory` 授权通过。
- `AVIATION_FACT` 类型不得进入 `required` 或 `optional`。

## 11. memory_context 构造策略

`MemoryContextBuilder` 负责把 `MemoryHit` 转换为统一上下文。

映射规则：

- `preference` 且 scope 匹配：进入 `session_preference`。
- `profile` 或稳定偏好：进入 `learner_profile`。
- `summary`：进入 `dialogue_context`。
- `misconception`：进入 `misconception_record`。
- 最近反馈：进入 `recent_feedback`。
- 过期、冲突、低置信、高隐私：进入 `prohibited_memories`。
- 过期、stale、替代关系：写入 `temporal_notes`。
- 每条注入或禁止的记忆都进入 `memory_hits`。

`memory_boundary` 固定包含：

- 记忆只能影响表达、指代、教学路径和误解纠偏。
- 记忆不能作为航空事实证据。
- 用户说法与 RAG 冲突时，以 RAG 或人工审核资料为准。

## 12. 主链路接入

### 12.1 AgentRuntime

`AgentRuntime.__init__` 必须接收 `memory_controller`。

当前错误路径：

```python
memory_context = MemoryContext()
```

必须替换为：

```python
memory_context = self.memory_controller.build_memory_context(
    MemoryRetrievalRequest(
        user_id=request.user_id,
        session_id=request.session_id,
        query_text=query_object.normalized_query or query_object.raw_query,
        task_type=query_object.intent_type,
        scene_state=scene_state,
        budget=self.memory_policy.max_context_items,
    )
)
```

`TextQueryRequest` 需要补充 `user_id` 和 `session_id`，否则主链路无法区分用户级记忆和会话级记忆。

### 12.2 PromptRuntime

Prompt 继续只接收格式化后的 `memory_context`，不得接收原始记忆记录。

注入顺序固定为：

```text
system_boundary -> task_type -> rag_evidence -> scene_state -> memory_context -> weak_points -> prompt_asset -> output_contract
```

如果当前配置与此顺序不同，应更新配置和测试。

### 12.3 RetrievalController

`RetrievalController.plan_retrieval` 可以读取 `memory_context.misconception_record` 和 `session_preference` 来调整查询意图或解释偏好，但不得将记忆转换成 `EvidenceItem`。

### 12.4 Generation

生成器可以使用 `session_preference` 控制表达，例如先结论、类比、简单解释。生成器不得基于记忆新增事实 claim。

### 12.5 SelfCheck

`BoundaryChecker` 保持并加强规则：

- `source_origin=memory` 的事实 claim 必须触发 `REWRITE_ONLY`。
- 如果回答文本出现“根据你以前说过某航空事实”，但 evidence 中没有来源，应触发边界问题。

### 12.6 Feedback

反馈模块产生 `memory_update_candidate` 后必须进入 `MemoryController.submit_candidate`，而不是停留在 `RewritePlan` 中。

单次偏好反馈默认只能进入 session scope；多次稳定出现、且治理通过后才能成为 long-term active preference。

## 13. 治理规则

### 13.1 事实隔离

禁止写入长期记忆：

- 用户声称的航空参数。
- 用户纠错中未经检索验证的型号、结构、历史事实。
- 模型生成但没有 evidence source 的事实。

这类内容只能进入：

- `fact_challenge_event`
- `misconception_candidate`
- `needs_verification`

### 13.2 隐私授权

`policy_memory` 必须优先约束：

- 原始语音保留。
- 学习轨迹保留。
- 演示报告导出。
- 长期画像保存。
- 删除请求。

如果授权不明确，默认不进入长期记忆。

### 13.3 冲突处理

同一用户、同一 scope、同一 predicate 的新旧记忆冲突时：

- 新记忆来自明确用户表达且置信度高：旧记忆 `superseded`。
- 新记忆来自模型推断：新记忆保持 `candidate` 或低置信 `active`。
- 新旧记忆无法判断优先级：建立 `contradicted_by`，两者都不进入 required context。

### 13.4 删除和归档

用户明确删除请求必须触发删除策略：

- 可硬删除的隐私数据应硬删除。
- 需要保留审计链的记录应脱敏后归档。
- 删除动作必须写审计日志。

## 14. 后台维护任务

维护任务必须统一从 `MemoryController.run_maintenance` 进入。

任务类型：

- `daily_decay_job`：降低长期未确认记忆得分。
- `expiry_job`：超过 `expires_at` 的记忆转为 `expired`。
- `conflict_scan_job`：扫描同一用户同一主题矛盾记忆。
- `promotion_job`：多次确认的候选提升为 active。
- `compression_job`：重复事件压缩为稳定画像。
- `privacy_delete_job`：执行用户删除和脱敏。
- `audit_job`：输出记忆命中与治理报告。

## 15. 配置设计

`configs/memory.yaml` 应扩展为：

```yaml
memory:
  store:
    provider: sqlite
    path: data/processed/memory.sqlite3
  max_context_items: 5
  default_expiration_days: 30
  low_confidence_threshold: 0.6
  stale_after_days: 14
  allowed_long_term_types:
    - preference
    - misconception
    - summary
    - policy
    - reflection
    - prompt_asset_candidate
  retrieval_weights:
    semantic_relevance: 0.30
    scope_match: 0.20
    scene_match: 0.15
    confidence: 0.15
    stability: 0.10
    recency_bonus: 0.10
    explicit_confirmation_bonus: 0.10
    expiry_penalty: 0.40
    conflict_penalty: 0.50
    privacy_penalty: 1.00

    default_long_term_allowed: false

  semantic_index:
    enabled: true
    embedding_provider: providers.embedding.default
```

配置缺失时抛出明确错误，不使用业务默认值。

## 20. 风险与控制

### 20.1 语义索引质量不足

控制方式：语义索引只作为记忆召回信号之一，不允许单独决定注入。必须结合 scope、权限、时间和状态。

### 20.2 记忆污染事实链

控制方式：`MemoryType.AVIATION_FACT` 不进入 active；self_check 检查 memory-origin fact；生成阶段只绑定 evidence id。

### 20.3 过度个性化

控制方式：context budget、scope、expires_at、stability score、prohibited list 共同约束。

### 20.4 冗余接口回潮

控制方式：删除旧接口，并增加 `rg` 验收命令检查：

```powershell
rg -n "InMemoryEventLog|InMemoryMemoryStore|upsert_memory|memory_context = MemoryContext\\(" src tests
```

验收时上述命中必须为 0，除非出现在设计文档或历史报告中。

# 语音交互与实时会话系统差异修复任务

## 1. 文档定位

本文档把《翼览无余智能体模块设计文档 V2_增加语音交互》、`docs/项目总控/task.md`、`docs/项目总控/spec.md`、`docs/项目总控/harness.md` 与当前代码之间的差异，转换为可执行、可验收的 P7 修复任务。

本文档是任务与目标定义，不是逐行编码步骤。后续实施必须以配套的《语音交互与实时会话系统差异修复实施计划》为执行顺序，并在每个任务完成后运行本任务定义的验收测试。

## 2. 修复结论与目标

当前代码已经具备 Mock-first 语音骨架，包括语音状态枚举、Mock ASR/TTS/VAD、基础术语替换、低置信澄清标记、Prompt 资产元数据和进入可信问答主链路的入口。但它尚未形成设计要求的实时语音闭环：音频传输、流式端点检测、可替换 Provider、会话级编排、场景指代澄清、结构化 spoken answer、可取消 TTS、barge-in 到 P6 的闭环、语音事件审计和完整指标都未落地。

本轮修复目标是把现有 `MockVoiceLoop` 重构为“契约清晰、配置驱动、可替换、可测试、可中断、可审计”的级联式 Voice RAG 系统，同时保留 Mock/Offline 模式，使测试和本地演示不依赖真实外部服务。

目标主链路为：

```text
音频帧 -> 实时传输 -> VAD/端点检测 -> 流式 ASR
       -> 航空术语纠错 -> 口语查询标准化/场景绑定
       -> 低置信或指代不明时澄清
       -> 正式 RAG -> 回答生成 -> 自我检查
       -> spoken_answer 规划 -> 流式 TTS
       -> barge-in 取消旧播报 -> P6 反馈解析/改写/重新检索
       -> 受治理的记忆候选与语音指标
```

## 3. 核心实施原则

1. 语音模块不得绕过 P1/P3/P4/P5 直接回答航空事实。
2. 低置信 ASR、未完成转写、无场景对象的指代表达不得进入正式检索。
3. `spoken_answer` 必须来源于已经通过证据门控和自我检查的 `answer_envelope`。
4. barge-in 的第一动作必须是取消旧 TTS，之后才能解析反馈。
5. 表达类反馈锁定原证据；对象类反馈重新绑定并检索；事实质疑重新取证；长期偏好只生成候选记忆并进入 P2 治理。
6. 所有 Provider、阈值、词典、传输和最大语音长度必须配置化，业务代码不得读取散落常量。
7. Mock Provider 与真实 Provider 使用同一接口和同一契约，不保留平行的 Mock-only 主流程。
8. 优先通过职责重构消除根因，不用条件分支堆叠临时补丁。
9. 删除确认无调用、无兼容价值、无测试依赖的接口和代码；删除前必须完成引用扫描和替代路径验证。
10. 默认不持久化原始音频；转写、指标和事件输出遵守脱敏、最小化与授权边界。
11. 不引入端到端 speech-to-speech 模型作为事实问答主链路。
12. 不在本轮接入真实生产密钥、真实生产数据库或需要联网的生产服务。

## 4. 范围与非目标

### 4.1 本轮范围

- WebSocket 实时音频原型及内存 Mock transport。
- 音频帧、语音输入事件、ASR 事件、语音查询、语音回答、播放句柄和语音指标契约。
- VAD、停顿、端点检测和 session 隔离。
- 流式 ASR Provider 接口、partial/final 管理和 Mock Provider。
- 航空术语词典、场景辅助纠错和不确定性保留。
- 口语意图、目标实体、场景指代、澄清和最终检索门控。
- 可选的轻量预检索与 final transcript 正式检索隔离。
- spoken answer 三段式结构、时长/文本预算和发音词典。
- 流式 TTS Provider、播放取消和文字降级。
- barge-in、P6 反馈改写、重新检索和记忆候选治理接线。
- 指标、trace、错误码、测试、部署说明和死代码清理。

### 4.2 非目标

- 不实现浏览器麦克风 UI 或完整前端产品界面。
- 不绑定 OpenAI、SenseVoice、CosyVoice、sherpa-onnx 等任一真实供应商。
- 不实现端到端语音到语音事实回答。
- 不保存或训练用户声纹，不做说话人身份识别。
- 不建设生产级媒体服务器、集群级会话路由或跨地域容灾。
- 不把语音转写内容直接写入航空事实库。

## 6. 目标架构与职责边界

### 6.1 契约层

统一定义以下对象，并保证 Mock、WebSocket、Provider、编排器和测试共享同一结构：

- `AudioFrame`：`session_id`、`turn_id`、`audio_stream_id`、`sequence_no`、`payload`、`sample_rate`、`channel_count`、`client_timestamp_ms`、`energy`、`scene_state`。
- `VoiceInputEvent`：音频开始、活动、停顿、结束、错误和断连事件。
- `ASRResult`：`raw_transcript`、`confidence`、`is_final`、`start_ms`、`end_ms`、`language`、`candidates`、`provider`。
- `VoiceQueryObject`：设计要求的全部字段，包括 `intent_type`、`target_entity`、`target_aircraft`、`target_component`、`scene_object_id`、`needs_clarification`、`retrieval_priority` 和检索审计字段。
- `SpokenAnswer`：`answer_brief`、`spoken_steps`、`follow_up_prompt`、`source_answer_id`、`source_evidence_package_id`。
- `VoiceAnswerObject`：显示答案、spoken answer、TTS 配置、可中断策略和证据引用。
- `PlaybackHandle`：播放 ID、状态、已播报位置、取消接口和完成事件。
- `BargeInEvent`：被打断回答、时间、位置、反馈文本、分类和后续动作。
- `VoiceMetricRecord`：延迟、质量、长度、打断和隐私字段。

### 6.2 Provider 层

- `VADService` 只负责音频活动判断，不负责业务路由。
- `EndpointDetector` 组合静音持续时间、ASR final/partial 和语义完整性。
- `ASRProvider` 只负责把音频段转换为 partial/final `ASRResult`。
- `TTSProvider` 只负责把 `SpokenAnswer` 转换为可取消的音频流。
- `AudioTransport` 只负责接收/发送事件，不直接调用 RAG。
- Provider 创建由配置注册表负责，禁止在 `VoiceSession` 中硬编码 Mock 类。

### 6.3 会话编排层

`VoiceSessionOrchestrator` 是唯一主编排入口。它按 `session_id` 持有状态机、当前 turn、ASR 缓冲、预检索句柄和 TTS 播放句柄。状态机变化必须产生审计事件，并可由测试读取。

编排器只能通过 `AppPipeline` 进入可信主链路，通过 P6 公共接口处理反馈，通过 P2 公共接口提交候选记忆。它不得直接访问向量索引、生成器、记忆仓储或 TTS Provider 内部状态。

### 6.4 适配与兼容层

保留一个基于统一编排器的 `MockVoiceClient` 供单测和 smoke eval 使用。旧 `MockVoiceLoop` 在所有调用方迁移后删除，不保留两条业务路径。

## 7. 详细任务拆分

## T0：治理门禁与基线冻结

### 目标

在不违反 `harness.md` 的前提下，明确跨模块改动授权、依赖边界和当前行为基线。

### 详细任务

1. 在 P7 总控规格中记录本次差异修复范围、受控跨模块文件和允许的轻量 WebSocket 依赖。
2. 记录禁止项：真实密钥、生产服务、端到端 speech-to-speech、原始音频默认落盘。
3. 运行并保存语音专项、全量 pytest、compileall、deployment validate、smoke eval 的基线结果。
4. 扫描 `MockVoiceLoop`、`VoiceTurnEvent`、`MockAudioTransport`、`MockVADService`、`BargeInController` 的全部引用，形成迁移清单。
5. 对现有 API/契约做快照，防止无意破坏文本问答接口。

### 完成标准

- 基线测试全部通过，失败项已记录且没有被带入下一任务。
- 每个待删除符号都有调用方清单和替代接口。

## T1：统一语音契约与错误模型

### 目标

建立所有语音组件共享的单一数据契约，消除散落 dataclass、字段缺失和无法审计的问题。

### 详细任务

1. 新建 `src/voice/contracts.py`，集中定义音频、ASR、查询、回答、播放、打断和指标对象。
2. 对标设计文档补齐字段、字段类型、必填校验、置信度范围、时间戳和枚举。
3. 为可序列化对象实现稳定 `to_dict/from_dict` 边界，拒绝未知关键字段静默丢失。
4. 新建 `src/voice/errors.py`，定义传输、ASR、端点、TTS、状态、配置和协议错误码。
5. 将 `core.contracts.VoiceTurnEvent` 合并到新契约或升级为统一契约入口，禁止保留两个同名但字段不同的对象。
6. 迁移测试使用新契约；旧契约确认无引用后删除。

### 完成标准

- 设计要求的四类核心对象和运行时辅助对象全部有唯一实现。
- partial/final、场景对象、证据包、TTS 播放和打断信息能够完整序列化。
- 旧契约零引用，契约测试覆盖有效、缺失、越界和未知字段输入。

## T2：配置模型、Provider 接口与工厂

### 目标

让所有语音行为由 `configs/voice.yaml` 驱动，并建立真实/Mock 共用的可替换接口。

### 详细任务

1. 定义 `VoiceSettings`，一次性解析 transport、采样率、声道、帧长、VAD、端点检测、ASR、TTS、barge-in、词典、时长和隐私配置。
2. 统一配置键名为 `asr_low_confidence_threshold`，删除现有歧义键 `low_confidence_threshold`。
3. 增加配置值范围验证：采样率、声道、帧长、阈值、静音窗口、最大播报秒数必须合法。
4. 定义 `AudioTransport`、`VADService`、`EndpointDetector`、`ASRProvider`、`TTSProvider` 协议。
5. 建立 Provider registry/factory；未知 provider 在启动时失败，不在首个请求时失败。
6. 让 Mock Provider 通过相同 factory 创建，不允许编排器直接实例化 `MockASRProvider` 或 `MockTTSProvider`。
7. 为 pronunciation lexicon 和 terminology lexicon 定义独立 UTF-8 配置文件及加载器。

### 完成标准

- 修改 `voice.yaml` 能实际改变阈值、最大长度和 Provider。
- 错误配置产生明确 `VoiceConfigError`。
- 代码搜索无业务层硬编码的 `0.65`、`0.2`、`20` 或固定纠错字典。

## T3：实时传输、VAD 与端点检测

### 目标

实现可测试的 WebSocket 音频原型和按会话隔离的端点检测链路。

### 详细任务

1. 实现内存 transport 和 WebSocket transport，二者消费相同 `AudioFrame`。
2. 定义握手消息、音频帧消息、场景更新、结束、取消、错误和服务端事件格式。
3. 校验序列号、采样率、声道、frame payload 上限和 session/turn 一致性。
4. 将 VAD 状态从 Provider 实例全局变量迁移到 session/turn 上下文，避免跨会话污染。
5. 补齐 `voice_pause`，使用静音累计窗口而不是单帧静音立即结束。
6. `EndpointDetector` 结合静音、ASR final 和语义完整性决定 `speech_final`。
7. 处理乱序帧、重复帧、空 payload、断连和超时；错误不能触发 RAG 重跑。

### 完成标准

- 10/20/30ms 模拟帧均可形成稳定 turn。
- 短停顿产生 pause 而非提前结束，长静音产生 voice_end。
- 两个并发 session 的 VAD/端点状态完全隔离。
- WebSocket 原型可完成握手、发送帧、接收状态和正常关闭。

## T4：流式 ASR、航空术语纠错与口语查询标准化

### 目标

把 partial/final ASR 转换为完整、保守、可审计的 `VoiceQueryObject`。

### 详细任务

1. Mock ASR 支持可配置 partial/final 事件序列和时间戳。
2. 编排器只允许 final transcript 进入正式检索；稳定 partial 仅可触发预检索。
3. 术语纠错从硬编码字典迁移到词典加载器，支持规范写法、别名、读法和上下文标签。
4. 将 Prompt 资产从“只记录元数据”改为可选的结构化模型纠错路径；模型不可用时走确定性词典路径。
5. Prompt 路径不得凭空补全不确定术语；低置信候选必须保留 uncertainty 并触发澄清。
6. 标准化器输出意图、目标实体、航空器、部件、场景对象、澄清原因和检索优先级。
7. 接入已有 scene binding；“这个/这里/旁边那个”无唯一对象时必须澄清。
8. 引入最近一轮对话只用于指代消解，不作为航空事实证据。

### 完成标准

- “航道比”可纠正为“涵道比”；不确定结果会追问而非强改。
- “这个是什么”无 scene object 时不调用 AppPipeline。
- partial transcript 永不进入正式检索。
- `VoiceQueryObject` 满足设计文档和 harness 的全部字段要求。

## T5：会话编排、状态机与 Voice RAG 门控

### 目标

以持久的 session orchestrator 替换每轮新建、返回即丢弃的 `MockVoiceLoop`。

### 详细任务

1. 实现 `VoiceSessionOrchestrator` 和按 session 管理的上下文仓储。
2. 将状态变化、原因、turn ID 和时间戳写入 transition audit。
3. 把 VAD、ASR、标准化、澄清、AppPipeline、spoken answer 和 TTS 串成单一路径。
4. 把 `user_id`、`session_id`、`turn_id` 和 scene state 传入主管线，确保记忆与 trace 可关联。
5. 低置信、空转写、非 final、场景指代不明一律进入 CLARIFY。
6. 实现 lightweight pre-retrieval 抽象；其结果只能缓存候选，不能生成答案或成为最终证据包。
7. final transcript 到达后取消过期预检索，并通过 AppPipeline 执行正式检索与重排序。
8. 主管线返回错误或证据不足时进入文字/语音安全降级，不伪造成功回答。

### 完成标准

- 会话状态可跨多个音频帧和打断事件持续存在。
- 高置信 final query 只调用一次正式 AppPipeline。
- session/user 身份完整传递到记忆和 trace。
- 预检索结果不能绕过正式 evidence package。

## T6：结构化 spoken answer 与可取消 TTS

### 目标

从已通过主链路的回答生成可听、短、可中断的结构化语音输出。

### 详细任务

1. 实现 `SpokenAnswerPlanner`，输入最终 `AnswerEnvelope`，输出三段式 `SpokenAnswer`。
2. 强制保留来源 answer ID 和 evidence package ID，禁止引入新事实或新 claim。
3. 将 spoken Prompt 真正交给模型客户端执行；模型不可用或结构校验失败时使用确定性压缩器。
4. 同时执行字符预算、句数预算和估算时长预算；超限时重新压缩，不只截断 duration 元数据。
5. pronunciation lexicon 在 TTS 前转换读法，但不得改变屏幕显示文本和事实内容。
6. `TTSProvider.synthesize_stream()` 返回 `PlaybackHandle` 和音频 chunk 流。
7. 播放句柄支持原子取消、幂等取消、已播报位置和首包时间记录。
8. TTS 失败保留 display answer，不重跑 RAG，并向客户端发送明确降级事件。

### 完成标准

- spoken answer 包含一句结论、2-3 句解释和最多一个追问。
- 超过配置预算的输入被实际压缩，输出文本和估算时长都合规。
- TTS 可在播放中取消，取消后不再产生新音频 chunk。
- Prompt 执行不是只记录模板元数据。

## T7：barge-in、P6 反馈改写与记忆治理闭环

### 目标

实现“先停播、再理解、后处理”的完整打断闭环。

### 详细任务

1. SPEAKING 状态收到 voice_start 时立即调用当前 `PlaybackHandle.cancel()`。
2. 记录 answer ID、播放位置、打断时间、partial/final 反馈和取消耗时。
3. 状态转换必须经过 `SPEAKING -> INTERRUPTED -> REWRITE/CLARIFY`。
4. 使用 P6 `FeedbackParser` 分类表达变化、对象错误、事实质疑、停止和长期偏好。
5. 表达变化锁定 evidence package，只重写 spoken answer。
6. 对象错误重新绑定 scene object，并执行新的正式检索。
7. 事实质疑进入 RETRIEVE_MORE/重新取证，不直接采信用户陈述。
8. 明确长期偏好生成带 source event、user/session、置信度和 expires_at 的候选记忆，提交 P2 治理。
9. 临时要求只保存在当前会话上下文，不写长期记忆。

### 完成标准

- 打断测试能证明旧音频已经停止，而不是只生成事件。
- “讲简单点”不触发新检索；“你说错了”触发重新取证；“旁边那个”触发重绑定。
- 未授权、低置信或事实型语音内容不能写入长期记忆。

## T8：语音指标、trace、隐私与错误降级

### 目标

建立可验收、可追踪且不泄露原始音频的语音观测能力。

### 详细任务

1. 记录 ASR confidence、实体识别正确性样本、VAD 误切、端到端首响、TTS 首包、barge-in 响应和 spoken answer 长度。
2. 记录状态转换、Provider、配置快照 ID、澄清原因和降级动作。
3. trace 只输出 audio event ID、摘要和指标，不输出原始音频 payload。
4. raw transcript 的日志级别、保留策略和脱敏方式由 privacy config 控制。
5. 对 transport、ASR、TTS 和 session timeout 定义用户可理解的错误事件。
6. ASR/TTS 故障不得重复运行已完成的 RAG；可用文字答案时优先降级为文字。
7. 指标记录失败不得破坏用户主流程，但必须生成受控审计错误。

### 完成标准

- trace 可以还原一轮语音状态与决策，但不能还原原始音频。
- 所有设计要求的延迟和长度指标都有实际采集点。
- 故障注入测试覆盖 transport、ASR、TTS、指标写入和取消失败。

## T9：外部协议、应用入口和部署契约

### 目标

提供可被前端或本地测试客户端稳定调用的实时语音协议。

### 详细任务

1. 定义 WebSocket 握手、客户端消息、服务端消息、错误和关闭码。
2. 明确二进制音频帧与 JSON 控制帧的边界。
3. 增加健康检查：transport、Provider registry、词典和配置状态。
4. 更新 API contracts 和 deployment checklist，记录 Mock/Offline 与真实 Provider 的能力差异。
5. 提供本地 Mock client 示例，能够发送场景状态、音频帧、结束事件和打断事件。
6. 保持现有文本 API 和 CLI 行为不变。

### 完成标准

- 协议文档与代码 schema 一致。
- 本地客户端能跑通正常、澄清、TTS 失败和 barge-in 四条路径。
- deployment validate 能识别缺失配置、词典和 Provider。

## T10：测试体系重构

### 目标

让测试覆盖设计强约束，而不只是验证 Mock 类存在。

### 详细任务

1. 契约测试：字段、序列化、越界值和协议兼容。
2. 配置测试：有效配置、未知 Provider、键名迁移和词典加载。
3. VAD/端点测试：停顿、噪声、短语音、长静音和并发会话。
4. ASR/标准化测试：partial/final、术语、不确定性、场景指代和澄清。
5. Voice RAG 测试：低置信阻断、预检索隔离、正式检索唯一性和证据不足。
6. spoken/TTS 测试：结构、长度、发音、流式首包、取消和失败降级。
7. barge-in 集成测试：停播、状态、P6 分类、重检索、重绑定和记忆候选。
8. WebSocket E2E：握手、帧顺序、断连、重连、并发和关闭。
9. 隐私测试：普通日志和 trace 不包含原始音频字节。

## 10. 主要风险与控制措施

### 10.1 实时并发造成状态竞争

每个 session 只允许一个状态修改锁；音频接收、ASR、TTS 和 barge-in 通过显式事件队列协调。禁止多个 Provider 回调直接修改状态机。

### 10.2 partial transcript 污染正式证据

预检索缓存使用独立类型和命名空间，不能转换为最终 `EvidencePackage`。只有 final transcript 经标准化和门控后才能调用 AppPipeline。

### 10.3 TTS 取消不彻底

取消必须同时停止 Provider 生成和 transport 发送，并通过“取消后无新 chunk”测试。只修改状态字段不算完成。

### 10.4 语音反馈污染记忆

所有长期偏好必须关联源事件、用户、会话、置信度和过期时间，并经过现有 MemoryController 治理；事实型内容一律拒绝成为偏好记忆。

### 10.5 重构破坏文本主链路

语音通过 AppPipeline 公共入口接入，不修改文本查询语义。每个跨模块任务都必须运行文本 E2E 回归。

### 10.6 清理误删公共接口

删除前完成引用扫描、迁移调用方和一次完整回归；无法确认外部消费者的接口只标记弃用，不直接删除，并在 STATUS 记录原因。

## 11. 总体验收标准

只有同时满足以下条件，才能宣布本轮差异修复完成：

1. WebSocket Mock 原型能够处理连续音频帧和场景更新。
2. VAD/端点、ASR partial/final、标准化和澄清形成真实调用链。
3. 低置信、未完成转写、空文本和指代不明不会进入正式检索。
4. 高置信 final query 通过 AppPipeline 获得基于 evidence package 且经过自检的答案。
5. spoken answer 具有三段式结构并满足配置预算。
6. TTS 流可被 barge-in 立即取消，取消后无旧音频继续输出。
7. 表达、对象、事实和偏好四类反馈分别走正确路径。
8. user/session/turn/answer/evidence ID 在事件、trace 和指标中可关联。
9. 原始音频默认不落盘，日志与 trace 不泄露 payload。
10. 配置项全部生效，无硬编码 Provider、阈值、词典和长度限制。
11. 旧 Mock-only 主流程、重复契约和无引用代码已清理。
12. 专项、集成、E2E、全量回归、compileall、deployment validate、smoke eval 和 trace export 全部通过。
13. `STATUS.md` 完整记录当前阶段、文件变化、测试、harness 结论、未完成事项和下一阶段条件。

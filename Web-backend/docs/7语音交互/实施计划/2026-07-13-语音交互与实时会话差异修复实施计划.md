# 语音交互与实时会话系统差异修复实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` to implement this plan task-by-task. Every checkbox is a tracked execution step; do not skip review or verification gates.

**Goal:** 将当前 Mock-first 字符串语音入口重构为配置驱动、可替换、可中断、可审计的级联式 Voice RAG 实时会话原型，同时删除旧 Mock-only 主路径和重复契约。

**Architecture:** 采用契约优先的分层架构：transport/VAD/ASR/TTS 只提供可替换能力，`VoiceSessionOrchestrator` 按会话持有状态并通过 `AppPipeline` 进入可信 RAG 主链路。partial transcript 只能预检索，final transcript 才能正式检索；spoken answer 只从最终 `AnswerEnvelope` 派生；barge-in 必须先取消 TTS，再进入 P6/P2 治理。

**Tech Stack:** Python 3.13、dataclasses、typing Protocol、asyncio、`websockets==15.0.1`、pytest、现有 PromptRuntime/AppPipeline/Feedback/Memory/Trace 组件。

## Global Constraints

- 严格按 Task 0 → Task 11 顺序执行；不得带着失败测试进入下一任务。
- 语音模块不得绕过 P1/P3/P4/P5 直接回答航空事实。
- 低置信、非 final、空转写和场景指代不明不得进入正式检索。
- barge-in 必须先停止旧 TTS，再解析反馈。
- 原始音频默认不落盘；测试、日志和 trace 不得输出音频 payload。
- 不接入真实密钥、真实生产数据库或真实外部语音服务。
- `websockets==15.0.1` 是本轮唯一允许新增的运行时依赖；该版本官方文档确认支持 Python 3.13。
- Mock 与真实 Provider 必须使用同一 Protocol、契约和 orchestrator，不建立第二条 Mock 业务链。
- 每个任务先写失败测试，再实现，再运行专项与相关回归，再提交。
- 删除代码前必须先迁移全部调用方，并用 `rg` 证明零引用。
- 当前工作区存在用户未提交变更；执行前必须使用独立 worktree，禁止覆盖或提交无关文件。

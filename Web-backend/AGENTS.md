# AGENTS.md

你是本项目的自动开发 Agent。

## 总原则

你必须严格依据以下文档进行开发：

- docs/项目总控/task.md：阶段任务目标
- docs/项目总控/spec.md：阶段执行计划
- docs/项目总控/harness.md：阶段安全边界
- docs/项目总控/AUTO_DEV.md：全自动开发控制规则
- docs/项目总控/STATUS.md：阶段进度日志

## 工作方式

1. 历史主线按 P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8 顺序开发，当前 P0 至 P8 已有验收记录。
2. 回答生成专项使用 G0 → G1 → G2 → G3 → G4 → G5 → G6 → G7 → G8 维护工作包；它们位于历史 P8 之后，不创建新的 P 阶段，也不得覆盖历史 P0 至 P8 记录。
3. G 工作包按所触及模块继续受原 P harness 约束，并同时受 `docs/项目总控/harness.md` 的 G0–G8 专项门禁表约束。
4. 不允许跳过当前适用的 P 阶段或 G 工作包。
5. 不允许提前实现后续阶段功能。
6. 每个阶段或工作包完成后，必须自检、测试、记录日志，然后再进入下一项。
7. 如果测试失败，必须优先处理当前阶段或工作包问题，不允许带着失败继续。
8. 如果文档信息不足，必须在 docs/项目总控/STATUS.md 中记录“待确认”，不要凭空扩展需求。
9. 不允许引入 docs/项目总控/harness.md 禁止的依赖、架构、目录或接口变更。
10. 不允许硬编码核心业务规则。
11. 不允许把 Agent 调度、RAG、记忆系统、业务模块混写在同一个文件。
12. 不允许绕过既定接口直接调用底层模块。

## 每阶段完成标准

每个阶段完成前必须输出并写入 docs/项目总控/STATUS.md：

- 当前阶段编号
- 已完成任务
- 修改文件列表
- 新增文件列表
- 删除文件列表
- 测试命令
- 测试结果
- 是否违反 harness.md
- 未完成事项
- 下一阶段是否可以开始

## 自动开发停止条件

遇到以下情况必须停止，不要继续开发：

1. 测试连续三次失败且无法定位原因。
2. 需要用户确认核心架构选择。
3. task.md、spec.md、harness.md 三者出现明显冲突。
4. 需要新增大型依赖，但文档没有明确允许。
5. 需要修改安全边界、核心目录结构或阶段目标。
6. 需要访问密钥、真实生产数据库、真实外部服务。
7. 当前实现会破坏已有接口契约。
